# PlungePalz Places — Dev Infrastructure

This directory contains **AWS SAM infrastructure-as-code** for a self-contained **dev environment** of PlungePalz Places in **us-east-1**.

**⚠️ IMPORTANT**: This stack creates **NEW** resources with the `Places_*` table prefix and `plungepalz-places-dev-*` naming for all other resources. It does NOT import or modify any existing AWS resources in the account.

---

## What It Creates

### DynamoDB Tables (PAY_PER_REQUEST)
- **Places_Places**: Primary places table with DynamoDB Streams enabled
  - GSIs: `status-ts-index`, `slug-index`, `h3-r7-index`, `h3-r5-index`, `h3-r4-index`
- **Places_Submissions**: Submission records (no GSIs)

### Lambda Functions
- **Places_Search**: Search places by geo/type/activity (uses Algolia search key)
- **Places_GetByID**: Fetch single place by ID
- **Places_Submit**: Create submissions with verification codes
- **Places_AlgoliaSync**: DynamoDB Stream → Algolia sync (CONDITIONAL, disabled by default)
- **Places_AdminReview**: Admin-only place review (AWS_IAM auth)

### Lambda Layer
- **plungepalz-places-dev-generate-place-ai**: Anthropic SDK + AI generation logic from `backend/lambda_layers/generate_place_with_ai`

### API Gateway (REST)
- **Stage**: `dev`
- **Endpoints** (generated via SAM Events):
  - `GET /search` → Places_Search (no auth)
  - `GET /place/{place_id}` → Places_GetByID (no auth)
  - `POST /submit` → Places_Submit (no auth)
  - `POST /plungepalz_admin/review` → Places_AdminReview (AWS_IAM auth)
- **CORS**: Configured for `http://localhost:3000` (override with `AllowedOrigin` parameter)
- **Throttling**: 
  - `/search`: 5 req/sec, 10 burst
  - `/submit`: 5 req/sec, 10 burst
  - Stage-wide default: 10 req/sec, 20 burst
- **OPTIONS preflight**: Auto-generated by SAM for CORS

### IAM Roles (Least Privilege)
- One role per function
- Scoped to only the SSM parameters each function needs:
  - **Places_Search**: reads `app_id` + `search_api_key`
  - **Places_AlgoliaSync**: reads `app_id` + `write_api_key`, writes to DLQ
  - **Places_Submit**: reads Google API key
  - **Places_AdminReview**: Query on `status-ts-index`
- DynamoDB permissions scoped to stack's own tables/indexes/streams
- No fixed role names (CloudFormation-generated)

### CloudWatch Logs
- 14-day retention for all Lambda log groups

### SQS Dead Letter Queue
- **plungepalz-places-dev-algolia-sync-dlq**: Captures failed AlgoliaSync stream events (created only if AlgoliaSync is enabled)

## AlgoliaSync Function (Conditional)

**Places_AlgoliaSync** is **disabled by default** because the handler code (`backend/lambda_functions/Places_AlgoliaSync/index.py`) does not exist on the main branch.

To enable it after the handler is implemented:
```bash
./deploy.sh --env-file /path/to/secrets.env \
  EnableAlgoliaSync=true
```

Or pass it as a parameter override during deployment. When enabled, the function, its role, log group, DLQ, and DynamoDB stream event source mapping are all created.

## Deployment

### Prerequisites
1. **AWS CLI** configured with a profile (default: `plungepalz-dev`)
2. **AWS SAM CLI** installed ([docs](https://docs.aws.amazon.com/serverless-application-model/latest/developerguide/install-sam-cli.html))
3. **Python 3.13** (for building Lambda layer)
4. **Region**: Profile must be configured for `us-east-1`
5. **Credentials**: Valid AWS credentials with CloudFormation, Lambda, DynamoDB, IAM, API Gateway, SSM, and S3 permissions

### Step 1: Set API Credentials

**Option A: From an env file** (recommended for repeatable deploys)

Create a local, uncommitted env file (e.g. `/home/user/secrets/backend.env`) with:

```bash
ALGOLIA_APP_ID=YOUR_APP_ID
ALGOLIA_SEARCH_API_KEY=YOUR_SEARCH_KEY
ALGOLIA_WRITE_API_KEY=YOUR_WRITE_KEY
GOOGLE_PLACES_API_KEY=YOUR_GOOGLE_KEY  # Optional
ANTHROPIC_MODEL_ID=claude-3-5-haiku-latest  # Optional, defaults to claude-3-5-haiku-latest
```

**Note**: `ANTHROPIC_API_KEY` is NOT required by these functions and should NOT be in the env file (none of the 5 functions currently use it).

Then deploy with:

```bash
./deploy.sh --env-file /path/to/backend.env
```

The deploy script will:
1. Parse only the needed variables from the env file (secure, doesn't source the whole file)
2. Write them to SSM Parameter Store via temporary mode-600 files (SecureString for keys, String for app ID)
3. Build the SAM template with `sam build`
4. Deploy the built template
5. Never echo secret values or expose them in process lists

**Option B: Manual SSM parameter setup**

Run the interactive helper:

```bash
./setup-ssm-params.sh
```

It will prompt for each credential (values are not echoed) and write them to SSM.

Then deploy without `--env-file`:

```bash
./deploy.sh
```

### Step 2: Deploy the Stack

```bash
# Standard deploy (non-interactive)
./deploy.sh

# With env file
./deploy.sh --env-file /path/to/secrets.env

# Non-interactive mode (skip prompts, fail if not on TTY)
./deploy.sh --yes

# Guided deploy (first-time setup)
./deploy.sh --guided

# Enable AlgoliaSync (after handler is implemented)
./deploy.sh --env-file /path/to/secrets.env EnableAlgoliaSync=true
```

The script will:
1. Validate AWS credentials and region (enforces us-east-1)
2. Check or write SSM parameters
3. Run `sam build` to build Lambda layer dependencies and functions
4. Validate the template with `sam validate --lint`
5. Create artifacts bucket `plungepalz-places-dev-artifacts-<account-id>` if needed (separate stack)
6. Deploy via `sam deploy --template-file .aws-sam/build/template.yaml`
7. Print stack outputs

**Environment Variables**:
- `AWS_PROFILE`: Override default profile (default: `plungepalz-dev`)

## Tear Down

To delete the entire stack and all resources:

```bash
# Delete the main stack
aws cloudformation delete-stack \
  --stack-name plungepalz-places-dev \
  --region us-east-1 \
  --profile plungepalz-dev

# Wait for deletion to complete
aws cloudformation wait stack-delete-complete \
  --stack-name plungepalz-places-dev \
  --region us-east-1 \
  --profile plungepalz-dev

# Delete the artifacts stack
aws cloudformation delete-stack \
  --stack-name plungepalz-places-dev-artifacts \
  --region us-east-1 \
  --profile plungepalz-dev

# Optionally delete SSM parameters
aws ssm delete-parameters \
  --names \
    /plungepalz-places-dev/algolia/app_id \
    /plungepalz-places-dev/algolia/search_api_key \
    /plungepalz-places-dev/algolia/write_api_key \
    /plungepalz-places-dev/google/places_api_key \
  --region us-east-1 \
  --profile plungepalz-dev

# Optionally empty and delete the artifacts bucket
ARTIFACTS_BUCKET="plungepalz-places-dev-artifacts-$(aws sts get-caller-identity --profile plungepalz-dev --query Account --output text)"
aws s3 rm "s3://${ARTIFACTS_BUCKET}" --recursive --profile plungepalz-dev
aws s3 rb "s3://${ARTIFACTS_BUCKET}" --profile plungepalz-dev
```

**Note**: DynamoDB tables are deleted when the stack is deleted (no retain policy). Back up any data before tear down.

## Architecture Notes

### API Gateway Integration

Uses **SAM Events** (`Type: Api`) to generate API Gateway resources, methods, integrations, and Lambda permissions automatically. The deployed API includes:
- All HTTP methods defined in function Events
- OPTIONS methods for CORS preflight (auto-generated)
- Proper integrations with `AWS_PROXY` type
- Lambda invoke permissions

This approach is more maintainable than hand-writing `AWS::ApiGateway::Resource` and `AWS::ApiGateway::Method` resources.

### Algolia Integration

**Approach**: SSM Parameter Store with least-privilege IAM

- **app_id**: Plain `String` parameter (not secret)
- **search_api_key**: `SecureString` (Places_Search reads it at runtime via `ssm:GetParameter`)
- **write_api_key**: `SecureString` (Places_AlgoliaSync reads it at runtime via `ssm:GetParameter`)

IAM roles are scoped per function:
- `Places_Search`: Can only read `app_id` + `search_api_key`
- `Places_AlgoliaSync`: Can only read `app_id` + `write_api_key`

**Runtime Pattern**: Lambda functions retrieve parameters at cold-start via `boto3.client('ssm').get_parameter()` with `WithDecryption=True`, then cache them in global scope for warm invocations.

**Security**: 
- API keys never appear in CloudFormation outputs, stack parameters, or logs
- The deploy script uses temporary mode-600 files and `--cli-input-json file://` to avoid exposing secrets in process lists
- The env file is parsed (not sourced) to prevent leaking unrelated AWS credentials

### Missing Handlers

The template references `backend/lambda_functions/Places_AlgoliaSync/` which does not yet exist on the main branch. To avoid deployment failures, **AlgoliaSync is disabled by default** via the `EnableAlgoliaSync` parameter (default: `false`). When disabled, the function, its role, log group, DLQ, and stream mapping are all skipped via CloudFormation Conditions.

Enable it after Backend Bot implements the handler:
```bash
./deploy.sh --env-file /path/to/secrets.env EnableAlgoliaSync=true
```

### Artifacts Bucket

The deploy script creates a dedicated S3 bucket `plungepalz-places-dev-artifacts-<account-id>` (via a separate stack `plungepalz-places-dev-artifacts`) instead of using the default SAM-managed bucket. Benefits:
- Scoped to this project (prefix in name)
- Public access blocked
- Server-side encryption enabled
- 30-day lifecycle expiration for old artifacts
- Easy to identify and clean up

The artifacts stack is created automatically if the bucket doesn't exist.

## Troubleshooting

### Deploy fails with "Invalid parameter type"
- Ensure SAM CLI is up to date: `sam --version` (requires ≥1.40.0)

### "No such file or directory: .aws-sam/build/template.yaml"
- The deploy script runs `sam build` automatically. If it fails, check the error output and ensure Python 3.13 is available.

### Layer missing anthropic package
- Run `sam build` and inspect: `unzip -l .aws-sam/build/GeneratePlaceWithAILayer/python.zip | grep anthropic`
- Ensure `backend/lambda_layers/generate_place_with_ai/requirements.txt` contains `anthropic>=0.39.0`

### API returns 403 Forbidden for all requests
- Check API Gateway stage is deployed
- Verify Lambda permissions were created (SAM should handle this automatically)

### "Access Denied" when reading SSM parameters at runtime
- Verify IAM role has `ssm:GetParameter` permission for the specific parameter ARN
- Check the parameter exists: `aws ssm get-parameter --name /plungepalz-places-dev/algolia/app_id`

### "Template format error" during validation
- Run `sam validate --lint` for detailed errors
- Ensure you're in the `backend/infrastructure/dev/` directory
- Run `sam build` first (validation requires built template)

### Deployment hangs on "Waiting for changeset to be created"
- Check CloudFormation console for detailed error messages
- Verify IAM permissions (needs `CAPABILITY_IAM` for role creation)
